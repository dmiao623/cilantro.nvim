INTRODUCTION                                            *cilantro-introduction*

Cilantro is a file-based task manager for Neovim. Tasks and events are stored
as individual Markdown files with YAML frontmatter. Directories are used for
human grouping only. The main pane provides a queryable task list with an
optional calendar column, while files are edited as ordinary buffers.

==============================================================================
SETUP                                                        *cilantro-setup*

Add cilantro to your plugin manager, then call setup:
>lua
  require("cilantro").setup({
    task_dir = "~/tasks",
  })
<

With lazy.nvim:
>lua
  {
    "dustinm/cilantro.nvim",
    config = function()
      require("cilantro").setup({
        task_dir = "~/tasks",
      })
    end,
  }
<

==============================================================================
COMMANDS                                                  *cilantro-commands*

:Cilantro                                                        *:Cilantro*
  Open the cilantro task list.

:CilantroCreate [path/to/title]                            *:CilantroCreate*
  Create a new task. If no argument is given, prompts for one. The last
  path segment becomes the title; earlier segments become subdirectories
  under `task_dir`.

:CilantroCreateEvent [path/to/title]                  *:CilantroCreateEvent*
  Create a new event. Behaves like |:CilantroCreate| but writes an event
  file (`type: event`). See |cilantro-event-format|.

:CilantroRefresh                                          *:CilantroRefresh*
  Rebuild the index and re-render the task list.

:CilantroClose                                              *:CilantroClose*
  Close the cilantro UI (list, calendar, and peek windows).

:CilantroToggle                                            *:CilantroToggle*
  Toggle the cilantro UI.

KEYMAPS                                                    *cilantro-keymaps*

In the task list buffer:

  <CR>      Open task in peek split (lower horizontal split)
  x         Cycle status forward (todo -> in_progress -> done -> cancelled)
  X         Cycle status backward
  a         Create a new task (the task list is the tasks buffer)
  A         Create a new event (prompts for path/to/title)
  dd        Delete the task under the cursor
  f         Filter by status
  s         Change sort field
  S         Toggle sort direction (ascending/descending)
  se        Sort by end time
  sa        Sort alphabetically by title
  td        Toggle showing completed (done) tasks
  tp        Toggle showing file paths
  tc        Toggle the calendar column
  R         Refresh index and re-render
  <C-f>     Open task in focus mode (full window)
  q         Close cilantro

In the calendar buffer:

  <CR>      Open event in peek split
  a         Create a new event (the calendar is the events buffer)
  A         Create a new event
  dd        Delete the event under the cursor
  tc        Toggle the calendar column
  R         Refresh index and re-render
  <C-f>     Open event in focus mode
  q         Close cilantro

In the peek split:

  <C-f>     Toggle between peek and focus mode

All keymaps can be customized or disabled via |cilantro-configuration|.

CONFIGURATION                                        *cilantro-configuration*

Configuration is passed to `require("cilantro").setup()`:
>lua
  require("cilantro").setup({
    -- Required: path to the task directory
    task_dir = "~/tasks",

    -- Status values and their display order
    status_order = { "todo", "in_progress", "done", "cancelled" },

    -- Default status for new tasks
    default_status = "todo",

    -- Height of the peek split (in lines)
    peek_height = 15,

    -- Timezone offset appended to default start/end times.
    -- ISO-8601 offset: "-04:00" is UTC-4, "+00:00" or "Z" is UTC.
    timezone = "-04:00",

    -- Show a confirmation prompt before deleting a task or event.
    confirm_delete = true,

    -- Columns shown in the task list
    list_columns = { "status", "title", "end_time" },

    -- Calendar column settings
    calendar = {
      enabled = true,  -- show the calendar column by default
      width = 28,      -- width of the calendar column (in columns)
    },

    -- Panel layout settings
    layout = {
      -- Width ratio: file tree : events : tasks
      ratio = { 1, 2, 2 },
      -- File tree command: "netrw" runs :Explore; any other value is run
      -- as an Ex command (e.g. "Oil" runs :Oil).
      file_tree = "netrw",
    },

    -- Keymap overrides (set to false to disable)
    keymaps = {
      open = "<CR>",
      cycle_status = "x",
      cycle_status_back = "X",
      create = "a",
      create_event = "A",
      delete = "dd",
      filter = "f",
      sort = "s",
      sort_direction = "S",
      sort_end_date = "se",
      sort_alpha = "sa",
      toggle_done = "td",
      toggle_paths = "tp",
      toggle_calendar = "tc",
      refresh = "R",
      focus = "<C-f>",
      close = "q",
    },
  })
<

TASK FORMAT                                            *cilantro-task-format*

Each task is a Markdown file with YAML frontmatter:
>markdown
  ---
  type: task
  id: 01HT...
  title: Draft billing migration plan
  created_at: 2026-04-05T10:42:00Z
  updated_at: 2026-04-05T11:10:00Z
  start_time: 2026-04-05
  end_time: 2026-04-12
  task-data:
    status: in_progress
    completed_at:
    subtasks:
  event-data:
    length:
    recurring:
  ---
  Notes for this task go here.
<

Frontmatter is split into two parts. Shared fields sit at the top level
(`type`, `id`, `title`, `created_at`, `updated_at`, `start_time`,
`end_time`). Type-specific fields are nested under two blocks,
`task-data:` and `event-data:`.

Both blocks are always written, so every file has the same structure
regardless of its `type`. Only the block matching the file's `type` is
read; the other is ignored, but kept so the file can be converted by
changing `type`.

Task-specific fields, nested under `task-data:`, are `status`,
`completed_at`, and `subtasks`.

The `type` field defaults to `task` when absent. Filenames are the
slugified title with a `.md` extension. When the title is changed in the
frontmatter and the file is saved, the file is automatically renamed to
match and any open Oil.nvim buffers are refreshed.

The `updated_at` field is automatically set to the current time whenever
the file is saved.

When a new task or event is created, `start_time` and `end_time` both
default to the current date: `start_time` at `00:00` and `end_time` at
`23:59`, each with the configured timezone offset (see `timezone` in
|cilantro-configuration|, default `-04:00`). For example:
`2026-04-05T00:00-04:00`.

Status values: `todo`, `in_progress`, `done`, `cancelled`.

When sorting by end time (the default), tasks are grouped under date
headers. Tasks without an end time are sorted last.

The `start_time` and `end_time` fields accept either a date
(`2026-04-05`) or a date with a time (`2026-04-05T14:00`), optionally
followed by a timezone offset (`2026-04-05T14:00-04:00` or a trailing
`Z`). A date-only value is interpreted as `00:00` for `start_time` and
`23:59` for `end_time`.

Note: earlier versions used `start_date` / `end_date`, and stored all
fields flat at the top level (no `task-data:` / `event-data:` block).
Such files are still read correctly and are rewritten in the current
format the next time they are saved.

EVENT FORMAT                                          *cilantro-event-format*

An event is a Markdown file with `type: event` in its frontmatter:
>markdown
  ---
  type: event
  id: 01HT...
  title: Team standup
  created_at: 2026-04-05T10:42:00Z
  updated_at: 2026-04-05T11:10:00Z
  start_time: 2026-04-06T09:00
  end_time: 2026-04-06T09:15
  task-data:
    status:
    completed_at:
    subtasks:
  event-data:
    length: 15m
    recurring: weekly
  ---
  Notes for this event go here.
<

Events share the top-level fields with tasks (see |cilantro-task-format|)
and the same two-block structure. For an event the `task-data:` block is
present but unused; the event-specific fields live under `event-data:`.

Event-specific fields, nested under `event-data:`:

  length      Optional string describing how long the event lasts
              (free-form, for example `15m` or `1h`).
  recurring   Optional string, one of: `daily`, `weekdays`, `weekly`,
              `monthly`, `yearly`.

`start_time` and `end_time` follow the same date / date-time rules as
tasks (see |cilantro-task-format|).

Events are created with |:CilantroCreateEvent| and stored in the same
`task_dir` as tasks.

==============================================================================
CALENDAR                                                  *cilantro-calendar*

When the calendar is enabled (the default), |:Cilantro| opens a
three-panel layout: a file tree on the left rooted at `task_dir`, the
calendar of events in the middle, and the task list on the right.
Events appear in the calendar column; tasks appear in the list column.

The relative widths of the three panels are set by `layout.ratio`
(default `{ 1, 2, 2 }` — file tree : events : tasks). See
|cilantro-configuration|.

The file tree panel is opened by `layout.file_tree`. The default,
`"netrw"`, runs `:Explore` on `task_dir`. Any other value is run as an
Ex command — for example `file_tree = "Oil"` runs `:Oil` (oil.nvim). If
the command fails (for example the plugin is not installed) the panel
is skipped and only the calendar and task columns are shown.

Closing any panel (for example pressing `q`) closes all three together.

Both columns are grouped under shared date headers: events are grouped by
`start_time`, tasks by `end_time`, and the headers are aligned row-for-row
across the two columns. The two windows scroll together (mouse wheel,
`j` / `k`, `<C-d>` / `<C-u>`, etc.), so the dates always stay lined up.

The calendar column is shown only while sorting by end time (the default).
Choosing another sort field hides it; sorting by end time again, or
pressing `tc`, brings it back.

Recurring events are shown once, on their `start_time` date, with a `↻`
marker. Events without a `start_time` are omitted from the calendar.

HIGHLIGHTS                                              *cilantro-highlights*

The following highlight groups are defined with `default = true` so they
can be overridden in your colorscheme:

  CilantroStatusTodo          Linked to |hl-Keyword|
  CilantroStatusInProgress    Linked to |hl-WarningMsg|
  CilantroStatusDone          Linked to |hl-DiagnosticOk|
  CilantroStatusCancelled     Linked to |hl-NonText|
  CilantroTitle               Linked to |hl-Normal|
  CilantroTitleDone           Linked to |hl-DiagnosticOk|
  CilantroDate                Linked to |hl-Number|
  CilantroHeader              Linked to |hl-Comment|
  CilantroEmpty               Linked to |hl-Comment|
  CilantroEventTime           Linked to |hl-Number|
  CilantroRecurring           Linked to |hl-Special|
